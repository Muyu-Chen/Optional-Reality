# 几何物理关卡 — 02.2 至 02.4

三关位于基础反弹之后、面包店之前，已有 ID 不变。均使用 30 秒模拟时限，保留重力控制；规则通过队列准备，Send now 才执行。下面是可复现解法，符合物理的替代解法也接受。

| 关卡 / ID | 可复现操作 | 成功要求 |
| --- | --- | --- |
| 02.2 Not Too High / `multi-bounce` | `Set surface bounce to 0.9` 开始；第一次弹起后、第二次着地前发送 `Set surface bounce to 0.5` | 经两块蓝色板到达第二块上方出口；第二次过强会从出口上方经过 |
| 02.3 Brake Before the Edge / `friction-runway` | `Set surface friction to 0` 开始；整个滑块进入绿色区域后发送 `Set surface friction to 0.3` | 完整停在区域内，速度 ≤ 0.12 m/s，连续 0.75 秒 |
| 02.4 Catch, Don’t Bounce / `catch-cup` | `Set launch pad bounce to 1.1` 开始；飞行中发送 `Set cup bounce to 0` | 完整留在杯内，速度 ≤ 0.15 m/s，连续 0.8 秒 |

## 视觉与物理

- 蓝色回弹纹随实际弹性变化；青色跑道从光滑平行线变为密集粗糙纹。普通墙为灰色，目标为绿色，底部掉落边界为红色。
- 摩擦关是约束旋转的矩形滑块，使用 Matter.js 接触摩擦；没有把静摩擦当成小球的滚动阻力。跑道右侧开放，场景没有隐形侧墙接住滑块。
- 接球杯的发射板与杯底有独立初始材质、别名和修改权限，灰色杯壁固定。全局弹性在此关不开放，避免玩家误把两种用途一起修改；重力仍可修改。
- 杯底初始弹性 1.05，属于游戏允许的超弹性范围，回弹纹较大。降低杯底弹性不影响发射板，不在空中直接修改速度。
- 停靠目标用真实形状做完整包含检查，允许 0.5 世界像素的求解器接触穿透。仅触碰、高速经过、停在外面均不通关；离开或超速清零进度。绿色进度条反映真实停留时间，暂停冻结。

## 自动验证的容错

固定模拟频率为 120 Hz。下表记录实测窗口，不是玩家必须记住的参数。

| 条件 | 验证范围 |
| --- | --- |
| 第二次反弹前降弹性 | 起步后 tick 280、360、480、560 均通关，覆盖约 2.33 秒的发送窗口；不执行第二条并一直保持 0.9 时不通关 |
| 摩擦制动时机 | 滑块中心 x=420、450、500、550、600 均通关；首尾覆盖约 1.125 秒；x=250 或 665 制动不通关 |
| 摩擦强度 | 在停车区内使用 0.1、0.2、0.3、0.5 均通关；保持 0 会经过目标并掉落 |
| 接球杯发射强度 | 1.05、1.075、1.1、1.125、1.15 均可配合杯底 0 通关 |
| 降低杯底弹性的时机 | tick 250、360、480、600 均通关；也允许提前准备并发送两条独立规则 |

默认状态八关均不误通关。测试还覆盖命名与中文别名、未知表面拒绝、保护滑块、局部规则独立、API 权限、连续停留、暂停、队列补位、真实字幕、失败后重试和下一关顺序。

## 代码边界

关卡文件只放数据。`scene-bodies.ts` 创建圆球/滑块和开放边界，`goal.ts` 判定目标，`surface-target.ts` 解析名称。`geometry-renderer.ts` 组合 actor、surface、goal 三个独立绘图模块；运行时不按关卡 ID 写特殊通关逻辑。

执行 `npm test` 与 `npm run build`。完整记录见 [verification.md](./verification.md)，测试要求见 [testing.md](./testing.md)。
