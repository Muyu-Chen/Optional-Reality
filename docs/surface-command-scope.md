# 表面指令行为

玩家不需要理解“全局默认值”和“局部覆盖”的内部区别。通用的“把弹力改为 10”应让场景里可修改的表面一起变得更弹，按现有范围限为 1.5；明确说发射板或杯底时，才单独修改该表面。固定墙体、小球和关卡布局继续受保护。

## 统一执行约定

- `world.restitution` / `world.friction` 操作更新全局值，并同步所有具有该属性修改权限的局部材质。没有局部值的表面继续继承全局值，不产生冗余覆盖。
- `launch-pad` 等具体对象操作只修改对应表面；之后再次执行通用规则，仍会作用于它。
- 通用加法、减法和翻倍分别读取每个表面的当前值。例如发射板 0.1、杯底 1.05 翻倍后为 0.2、1.5（限幅），不会先按全局值 0 计算，再把两者清零。
- 同一消息保持操作顺序：先全部设为 0.8，再杯底设为 0，结果为 0.8 / 0；反序执行则两者均为 0.8。
- 重试恢复关卡独立初始材质；Undo 恢复整条消息执行前的材质。模型仍只生成一个 world 操作，不自行展开所有表面。

执行逻辑独立保存在 `shared/surface-materials.ts`，由共享规则执行器调用。模型提示词和关卡场景描述使用相同约定，权限、限幅和原子性检查继续保留。

## 玩家看到的内容

队列摘要直接标注 **All surfaces**、**Launch pad** 或 **Cup base**，不增加有关继承机制的警告。场景独立材质标签显示实际值，包括 0；无需打开参数面板就能确认地面发生了什么变化。原始输入和限幅信息仍可通过已有展开按钮查看。

## 复现与验证

用户在 Catch Tutorial 输入的两句，真实线上模型分别解析为 world 弹性 1.5 和 launch-pad 弹性 1。旧执行器让发射板继续保持初始 0.1，造成数值越大反而不弹的错觉。修复后，一般指令与点名发射板设为 1.5 在第一次发射板碰撞中得到相同速度，且都比设为 1 的反弹更强；杯壁保持原材质。

测试覆盖绝对／相对修改、独立当前值、上下限、零值、混合顺序、保护属性、失败原子性、真实碰撞、界面发送／下一条补位、Undo 与 Try again。原有九关解法回归仍需随发布快照一起执行。
