# Optional Reality — 游戏设计与开发约定

## 产品循环

通过自然语言改写规则、选择执行时机的 2D 物理解谜游戏。

观察 → 编写消息 → 解析排队 → Send now → 物理变化与字幕 → 尝试另一种时机。

物理引擎持续运行世界，AI 只编译受支持的声明式操作。关卡内不能直接移动、修改速度或删除任务物体。英文 UI，中英文输入；Web 首发，暂不引入 Electron、数据库或 3D。

## 关卡设计标准

主线沿用最早的斜坡与弹簧设想：同一条规则在一个阶段帮助玩家，在后续阶段可能妨碍目标，场景变化让玩家有理由重新选择规则与发送时机。下一轮优先方案见 [阶段式物理解谜](./phase-puzzles.md)。

- 先写清运动过程、目标与阶段之间的冲突，再选择机关；机关数量不作为升级标准。
- 玩家应能从几何结构、运动和反馈判断为何要改变规则。教学用明确示例，正式谜题避免依赖背诵精确数值。
- 接球杯作为局部材质的短教学，允许提前设置两块表面。停稳确认自动完成，不把 Hold 或等待时间当作新增玩法。
- 每关至少三颗真实可收集星星，位置定义满分路线；到达出口可过关，收齐后到达出口才获满分。教学采用宽容路线，不绑定指令数量或收集顺序。当前实现约定见 [星星评分与消息操作](./star-gameplay.md)。
- 收集物、出口要求和机关关系必须可见。成功依据世界状态，不检查是否按预设顺序发送了指定口令；符合物理的替代解法继续接受。
- 每个正式关卡先验证至少一个宽容的解法窗口，并解释提前执行、延迟执行和保持原规则各会发生什么。更多机关应带来新的决策。

## 等级与小关

主线优先发展几何物理玩法，统一「颜色 + 纹理 + 动作」与特性的映射，再增加机关。已加入多次反弹、摩擦跑道与接球杯，详见 [几何关卡说明](./geometry-levels.md)；更多候选机关见 [物理机关与视觉语言提案](./physics-mechanisms.md)。已有 ID 保持兼容。

等级表示教学顺序和机关组合，小关表示学习目标和布局。加速度向量、弹性、摩擦在全部实验中保持一致；不再通过关卡白名单隐藏基础物理量。预设设备、结构和任务物体的保护单独声明。

| 等级 | 机关与可学习能力 | 本轮小关 | 后续扩展 |
| --- | --- | --- | --- |
| 1 · Motion | 球、斜坡、固定弹簧、星星、出口；加速度和惯性 | 01 Gravity Lab；01.2 One More Turn：下落、反弹与方向变化 | 更多空间路线 |
| 2 · Collisions | 蓝色弹性与青色摩擦表面、滑块、停留目标 | 02.1 基础反弹；02.2 两次反弹先强后弱；02.3 完整停车；02.4 发射板与杯底分别控制 | 更多几何路线与材质组合 |
| 3 · Devices | 增加面包机/接触弹簧、向上风场、传送带、传感器与门 | 03.1 推荐面包机；03.2 推荐风场；03.3 综合搭配并联动开门 | 先扩展组合，再引入转轮 |

等级配置在 `client/src/levels/progression.ts`；关卡仍是独立数据文件。基础环境能力由共享声明生成，局部表面可以声明初始材质和 preset 保护；模型上下文与执行权限使用相同配置。初始状态仍严格校验。

03.1 的传送带与风场已预设；03.2 的传送带与面包机已预设。新手一次只需要学习一个可改机关。03.3 保留旧 ID `reality-breakdown`，兼容原有消息存储。转轮运行层保留并测试，当前主线不出现。

## 界面与状态

- Canvas 铺满浏览器视口。左上为目标、关卡、模拟倒计时；游戏控件使用轻量浮层。
- 右下半透明输入窗：Enter 提交，Shift+Enter 换行。提交只排队，规则暂不生效。
- 右上每条待发消息旁显示小号 Send now 和删除按钮；玩家可主动执行任意已准备消息。批量执行按列表顺序，错误消息可编辑或删除。
- 管理菜单提供排序、多选批量发送、历史、Undo 与清空。批量按队列顺序同时执行，不插入模拟时间。
- 消息经过本地解析或自动 AI 解析。等待模型时暂停世界；成功后仍暂停，等待 Send now 或 Resume。Send now 不调用模型。
- 左侧每条成功消息产生字幕，显示实际修改结果；4 秒可读、1 秒淡出；连续手动发送立即显示各自字幕，批量消息则按组依次显示。失败和仅解析不产生成功字幕。
- 暂停、教学、失败和过关互相区分。暂停菜单切关，过关可进入下一小关。
- 桌面右侧留出操作空间，出口和关键机关不能藏在浮窗下。窄屏把输入和队列移到底部，不让页面滚动。

## 结算、可读性与音乐

- 结算突出关卡编号、名称和三颗独立星形：取得的用金色，遗漏的保留清晰轮廓。普通通关与满分有不同标题和反馈，但真实评分规则不变。下一关为主要操作，重试次之；最后一关仍能重试或选择关卡。
- 暖纸面与深森林绿建立更明确的对比，辅助文字也保持可读。主要消息、输入和目标约 15–17px，辅助文字至少约 12px；逐条 Send now 保持紧凑。UI 与 Canvas 的蓝色回弹、青色摩擦、橙色推动、紫色加速度语义一致。
- 结算星形只做短入场动画，系统要求减少动态效果时关闭动画。桌面与窄屏都能访问下一关、重试和选关，必要时仅在弹窗内部滚动。
- 音乐使用本地 Web Audio 合成的原创轻量循环，无远程音轨请求。首次可信操作后才开始，保持低音量，提供 Music on/off 并保存偏好；页面隐藏时暂停，切关不叠加播放。
- 音乐不参与规则与物理，音频不可用、浏览器阻止播放或存储失败时游戏仍可操作。卸载清理音频节点、调度器和事件监听。

## 重试、教学与机关反馈

Try again：恢复关卡初始世界、30 秒模拟时限、消息额度与运行历史；保留原消息和已解析操作，重新等待发送。执行时仍校验操作；失败草稿可编辑。过期请求、字幕和选中状态清除。

Restart & reprepare messages：另行提供的高级操作，恢复世界并清除编译结果，保留文字。Undo 只恢复上一条规则与额度，不回滚运动；对应消息重新待发。完整 tick 时间轴 Replay 尚未实现。

面包机状态：idle → charging → launched。接触且功率大于零时，物理约束捕获面包；蓄力 0.6 秒模拟时间后解除约束并释放。物体离开触发区后才重新待机。关闭功率会解除蓄力约束，不发射。

第一次接触时额外暂停，突出压缩区域并解释作用。教学中可发送规则，但必须 Continue 才恢复运动。重试保留“已见教学”记录；暂停菜单的 Replay teaching 可以重新启用。切关或重载重新进入教学状态。

风扇正功率竖直向上施力，负功率向下；绘图箭头与实际方向一致。机关绘图读取真实状态，不自己推进物理。作用区域和碰撞坐标来自关卡定义。

## 指令与模型接口

复用 `/api/status` 和 `/api/compile`，使用 DeepSeek Flash 与可配置的 OpenAI 兼容 Chat Completions 服务。

请求包括关卡 ID、有序消息、当前规则、请求 ID、场景版本与队列 revision。模型获得场景别名、等级/关卡编辑权限、单位和范围；输出按消息 ID 对应的操作数组。相对变化在执行时计算；自动条件仅支持已有传感器触碰开门。蓄力、释放和教学暂停由本地机关负责，不要求玩家输入 compress/release。

已知错词保守纠正，原文和 Understood as 同时保留。有限数值超范围时由共享代码取最近边界，显示 Requested → limited to；相对规则在执行时限幅。非法目标、非有限值、歧义和不支持意图仍整批失败，保留现有世界。细节见 [消息语义](./command-language.md)。编辑、重试、切关取消旧请求并丢弃迟到结果。密钥只在后端，不进入客户端、日志或 Git。

## 开发阶段与完成标准

| 阶段 | 要求 | 验收 |
| --- | --- | --- |
| 0 基线 | 保存草稿、恢复可运行界面 | 类型检查、测试和构建通过 |
| 1 交互设计 | 先验证全屏布局与所有游戏状态 | 目标、队首和发送按钮可见，无页面滚动 |
| 2 接口与提示词 | 固定 JSON 先验证能力边界，再接模型 | 非法规则原子拒绝、相对操作正确、迟到响应无效 |
| 3 元素绘图 | 绘图独立于模拟，状态可辨认 | 形状/区域对应物理，压缩、气流、开门反馈明确 |
| 4 交互实现 | 队列、字幕、暂停、重试和过关闭环 | 不重复消费，消息补位正确，重试可比较时机 |
| 5 关卡实现 | 独立定义、每关一个主要新概念 | 每关有有效解法、默认失败和明确提示 |
| 6 验证平衡 | 自动测试与浏览器完整游玩 | 有容错窗口、教学冻结计时、合理尺寸可操作 |
| 7 交付 | 同步文档并按可运行批次提交 | main 正常推送，无密钥、依赖和构建产物 |

## 后续方向

先增加同级小关和机关组合，再扩展火、水等自然元素。每种新元素先定义作用规则、允许的指令、交互反馈和对象上限，再做图与关卡；不直接执行模型生成代码。自由沙盒、完整时间轴重放和自然元素均不计入本轮完成项。
